# 조건으로 후보 찾기 (입지 선택 → 살 수 있는 단지) — 검증과 구현 계획

작성 2026-10-09. 상태: **구현 완료(M0~M3)**, 결정 사항은 맨 아래.

## 1. 아이디어
- 후보(B)를 직접 지정하거나, **입지만 고르면** 내 집(A) 매도가·현금·대출을 반영해 **주담대 / 갭(전세 낀 매수)** 중 어느 방식이든 **살 수 있는 단지 후보**를 주고, 사용자가 그중에서 고른다.

## 2. 검증 결과

### 2-1. 가치
- 지금은 "B를 이미 알아야" 쓸 수 있다. 입지만 알아도 시작할 수 있게 되어 진입 장벽이 낮아진다. 기존 자금 계산(공식·시나리오)을 거꾸로 풀면 되므로 새 계산 엔진은 거의 필요 없다.
- 단, 이 결과는 "추천"이 아니라 **조건에 맞는 단지 목록**이어야 한다(아래 2-4).

### 2-2. 데이터 가능성 (실측, 2026-10-09)
- 후보 풀: 상승/주춤/하락 라벨이 붙은 단지 중 74~115㎡·12개월 거래 20건 이상 = **1,008개**.
- 가정: A 매도가와 대출 상환 후 순자금을 입력으로 받고, 대출 LTV 40%·상한 6억/4억/2억(15억·25억 기준)을 적용해 매수 상한과 후보 수를 계산한다.
- 구별 후보 수는 2~40개로 편차가 크고, **동 단위로 좁히면 중위 2개·최대 12개**. → 입지는 구 단위로 고르면 목록이 길어 정렬·필터가 필수이고, 동 단위는 목록이 짧다.
- **대출 상한이 15억에서 6억→4억으로 떨어지는 절벽**이 있다. 필요 자금은 가격에 따라 계속 늘고 절벽에서 위로 뛰므로 이진탐색이 유효하지만, 결과 상한이 절벽 직전(예: 15.0억)에 멈춘다. 경계값 테스트가 필요하다.

### 2-3. 모드별 실현성
| 모드 | 가능 여부 | 이유 |
|---|---|---|
| 주담대 | **가능** | 공식 이미 보유. 규제 파라미터만 룰 테이블로 분리하면 됨. |
| 갭(전세 낀 매수) | **부분 가능** | ① 전세 데이터가 없다(매매 실거래만 수집). ② 서울·경기 일부 토지거래허가구역은 2년 실거주 의무가 있고, 전세 낀 매수의 실거주 유예는 한시 제도이며 정부는 갭투자 허용이 아니라고 밝혔다. 규정이 바뀌는 중이라 룰을 사람이 갱신해야 한다. |

- 주담대 규제(2025-06-27 대책, 검색 요약 기준): 수도권 주담대 전입의무 6개월, 1주택자가 대출로 추가 매수 시 6개월 내 기존 주택 처분, 한도 6억(15억 이하). **DSR은 소득이 있어야 계산 가능**하다.
- 출처(검색 결과 요약만 확인, 원문은 열어보지 않음): [토허제 실거주 유예(머니투데이 2026-05)](https://www.mt.co.kr/estate/2026/05/11/2026051116392121727), [연말까지 유예(세계일보 2026-06)](https://www.segye.com/newsView/20260630513545), [토허구역 지정 서울·경기(YTN 2026-09)](https://www.ytn.co.kr/_ln/0102_202609171134592708), [가계부채 관리 방안(파이낸셜뉴스 2025-06)](https://www.fnnews.com/news/202506271142053672).

### 2-4. 위험과 대응
| 위험 | 대응 |
|---|---|
| 규정이 자주 바뀜 | 규칙을 코드가 아닌 **`rules.json`(값·출처·기준일·확인 상태)**으로 분리, 화면에 기준일 표시, 90일 넘으면 경고 |
| "추천"으로 읽힘 | 문구는 "조건에 맞는 단지", 정렬 기준을 사용자가 고르게 하고 **기본 정렬은 중립(12개월 거래 수)**. 상승률순 기본 정렬은 추격 매수를 부추길 수 있어 제외 |
| 시세는 추정(예측구간) | 매수가 중간값·범위로 **가능 / 빠듯 / 불가** 3단계 분류(범위 전체가 예산 안 = 가능, 중간값만 안 = 빠듯, 하한도 초과 = 불가) |
| 커버리지 한계 | 서울 25구·구리·하남·다산만 후보가 됨을 화면에 명시 |
| 소득 미입력 | DSR을 계산하지 않았다고 결과마다 표시 |

## 3. 설계

### 입력 (자금 계획 입력 재사용)
A 매도가(기본 추정 시세) · A 대출 잔액 · 보유 현금 · (선택) 연소득 · 모드(주담대/갭) · 입지(구·동 다중 선택) · 평형대(기본 A 전용 ±15㎡).

### 핵심 함수
- `maxBuy(profile, rules) → 구간별 상한가` : 대출 한도 구간(≤15억, ≤25억, 초과)별로 필요자금 부등식을 풀어 가장 높은 해를 반환(비단조 대응).
- `classify(est[mid,lo,hi], maxBuy) → 가능/빠듯/불가`.
- 갭 모드: 필요 현금 = 매수가 − 전세금 + 취득세 등. **1차는 전세가율을 사용자가 입력**(기본 60%, 추정 표시). 전월세 실거래 수집은 후속.

### 데이터
- 새 파일 `site/data/cand.json`: 단지별 평형별 `[전용, 표본수, 중간층 추정시세 mid, lo, hi]` (index.json은 평형 1개만 있어 부족). 예상 약 0.5MB.
- 새 파일 `site/data/rules.json`: `{asof, items:[{id, label, value, source, confidence}]}`. 포함: LTV, 대출 상한 구간, 전입의무, 처분기한, 취득세, 중개보수, 허가구역 시군구 목록(참/거짓/미확인).

### 화면
- 홈 FAB: "직접 검색 / 조건으로 찾기" 선택.
- `#/find`: ① 입지 시트(구 체크리스트 + 동 펼치기) ② 내 자금 요약(수정 가능, 자금 계획과 같은 입력 저장) ③ 결과 목록: 필터 칩(평형·상태·예산 3단계), 정렬 선택, 카드에서 "후보에 추가"·"비교"·"자금 계획".
- 결과 카드: 단지·평형·추정 시세·예산 분류·6개월 추세 배지(참고용 단지는 라벨 없이)·주변 대비·환금성·**빠듯한 이유**(예: 대출 상한 도달).

## 4. 구현 단계 (의존 순서)
| 단계 | 내용 | 검증 |
|---|---|---|
| M0 | `rules.json` + `maxBuy`/`classify` 순수함수(JS) | 독립 Python 구현과 무작위 1만 건 대조, 경계값(6·9·12·15·25억, 5천만·2억) |
| M1 | `cand.json` 생성, 후보 필터·정렬 로직 | 후보 수·정렬 불변식, 평형·입지 필터 단위 테스트 |
| M2 | `#/find` 화면, 후보 추가 흐름 | 헤드리스 Chrome 하니스(입지 선택→결과→추가), 화면 숫자 vs 독립 계산 |
| M3 | 갭 모드(전세가율 입력) + 허가구역 경고 | 필요 현금 공식 대조, 경고 노출 테스트 |
| M4 | (후속) 전월세 실거래 수집 → 전세가율 데이터화 | API 호출 필요, 별도 일정 |

수용 기준: ① 어떤 입력에서도 "가능"으로 표시된 단지는 자금 계획 화면에서 부족액 0 이하 ② 경계값에서 상한이 역전되지 않음 ③ 금지 표현(추천 등) 0건 ④ 룰 기준일 90일 초과 시 경고.

## 5. 사용자 결정 (2026-10-09)
1. **갭 모드 포함**, 단 **토허제 지역은 실거주 2년 의무 때문에 갭투자 불가**로 안내하고 결과에서 뺀다(보기 토글 제공).
2. **연소득 입력**: 가구 총 세전 연소득(1인·2인 구분 없음) + 기타 대출 연 원리금. 미입력이면 DSR 미반영 표시.
3. 입지 단위: 말씀이 없어 기본안(구 다중 선택 + 동 세분화)으로 구현.

## 6. 구현 현황 (M0~M3)
- `site/data/rules.json`: 지역별 규제지역·토허제 플래그, LTV, 대출 상한, DSR(40%, 스트레스 3.0%p), 항목별 출처·확인 상태·기준일(90일 초과 시 경고).
- `site/data/cand.json`: 단지별 평형별 중간층 추정 시세(중간값·범위). `build_data.py`가 생성.
- `app.js`: `loanLimit`/`needFor`/`maxBuy`/`classify`(순수 함수), `#/find` 화면, 입지·동 선택 시트, 자금 계획의 소득 기반 대출 자동 계산·토허제 안내·전세 승계/거주 보증금 항목.
- 가정값(화면에서 수정 가능): 금리 4.0%, 만기 30년, 전세가율 60%. 남양주 다산동은 비규제·비토허제로 가정(확인 필요).
- M4(전월세 실거래로 전세가율 데이터화)는 API 호출이 필요해 후속.
- 테스트: 독립 Python 구현과 대조(예산·최대 매수가·가능/빠듯/불가 개수·정렬), 토허제 갭 차단 안내, 규칙 기준일 경고, 입지·동 선택 흐름, **'가능' 단지를 자금 계획으로 열면 부족액이 없음(주담대·갭)**.
