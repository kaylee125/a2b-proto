# 갈아탈까 | A→B 갈아타기 모니터

내 집(A)과 후보(B)의 실거래 흐름을 보고, 갈아탈 자금까지 계획하는 프로토타입입니다.

## About

국토교통부 아파트 매매 실거래(2016-10 ~ 2026-09) 947,018건, 6,154개 단지를 단지 단위로 정리해 보여주는 정적 웹 앱입니다. 수록 지역은 서울 25개 구, 구리, 하남, 남양주 다산동, 수원(장안·권선·팔달·영통), 성남 분당, 안양 동안, 화성 동탄구입니다.

가격이 오르는지 보는 데서 멈추지 않고, 갈아타려면 돈이 얼마나 필요한지와 내 소득으로 살 수 있는 단지가 어디인지까지 이어서 봅니다. 모든 수치는 추정이고 투자 권유가 아닙니다. 입력한 정보는 서버로 보내지 않고 브라우저에만 저장합니다.

데이터를 보여주기 전에 "이 숫자를 믿어도 되는지"부터 확인하는 것을 원칙으로 합니다. 추세는 불확실성 범위와 함께 표시하고, 거래가 적은 단지에는 결론을 내리지 않고 "참고용"으로 둡니다. 규정 값에는 기준일과 확인 상태를 붙입니다.

## What It Does

- **6개월 추세와 시세 범위**  
  단지 안에서 층·평형 차이를 보정한 회귀로 최근 6개월 변화율을 계산해 상승·주춤·하락과 90% 범위를 표시

- **주변 입지 대비와 10년 흐름**  
  같은 동·구 단지와의 순위 비교, 2016년부터의 분기 지수, 2020~22년 고점 대비 낙폭(하락기 방어력)과 회복 분기

- **A↔B 비교와 자금 계획**  
  두 단지를 나란히 비교하고, 취득세·중개보수·법무비·이사비를 포함한 필요 자금과 시나리오·민감도 계산

- **조건으로 후보 찾기**  
  입지 → 살 방법(주담대/갭) → 가구 연소득·자금을 넣으면 가능·빠듯·불가 단지 목록 제공. LTV·대출 상한·DSR(스트레스 금리 가산)과 토지거래허가구역(갭 불가)을 반영

- **개인정보**  
  소득·취득가 등 입력은 `localStorage`에만 저장하고 외부 요청은 없음

## Selected Engineering

### 독립 검증으로 추세 엔진 결함을 찾아 수정

작성자가 아닌 에이전트 6개가 규제 값, 추세 엔진, 데이터 무결성, 후보 찾기 로직, 코드, 보안을 나눠 검증했습니다. 같은 작성자의 테스트는 같은 오해를 공유할 수 있어, 검증 계획(`docs/verification-plan.md`)을 따로 세우고 서로 결과를 보지 않게 진행했습니다.

- 최근 거래가 없는 단지에서 꺾임 모델이 마지막 거래 이후를 외삽해 -54%·"확실 하락" 같은 극단값을 내는 결함을 발견. 보고된 근거가 틀린 비교(수준 비교)였던 것도 직접 재확인해 바로잡음
- 최근 3개월 거래 2건 이상 조건을 추가. 후보 가드 여러 개를 독립 분기 지수와 비교해 하락 재현율은 유지하고 극단값만 줄이는 조건으로 선택
- 규제 값 서술 3건(스트레스 금리 적용 기간, 토허제 갭투자 서술, 남양주 와부읍 서술)을 공식 출처 기준으로 정정하고, 일시적 2주택 처분기한 안내를 추가
- 불변식 기반 무작위 테스트 1만 건에서 위반 0건, 국토부 API 재조회 50건 일치, 분기 지수 수작업 재계산 오차 0.00%

### 데이터 확장 시 기존 결과 무변동 검증

수원·분당·동안·동탄구 7개 코드를 추가해 단지를 5,040개에서 6,154개로 늘렸습니다. 기존 5,040개 단지의 추세·주변 비교·후보·10년 지수가 추가 전과 완전히 같음을 비교로 확인했고, 새 지역은 독립 분기 지수와 상관 0.80(서울 0.78)을 확인했습니다.

### 행정구역 개편 대응

2026-07 개편으로 화성시 옛 코드(41590)가 전 기간 0건이 된 것을 확인하고 동탄구 코드(41597)로 수집했습니다. 월별로 0건인 코드를 경고하도록 수집 스크립트에 넣어, 조용히 데이터가 빠지는 일을 감지합니다.

## 실행

먼저 공공데이터포털에서 "아파트 매매 실거래가 상세 자료" 활용신청 후 `.env.example`을 `.env`로 복사해 `DATA_GO_KR_SERVICE_KEY`를 채웁니다(환경변수로 줘도 됩니다). `tools/extract_trades.py`는 선택적으로 `data/dasan.db`(다산동 일일 수집 SQLite)를 읽고, 없으면 그 부분만 건너뜁니다. 생성 데이터(`cache/`, `data/`, `site/data/`)는 저장소에 없어서 아래 순서로 직접 만들어야 화면이 채워집니다.

    python3 tools/fetch_history.py 201610 202310   # 과거 월별 실거래 → cache/data/ (이어받기, 429면 30분 재시도)
    python3 tools/fetch_history.py 201610 202609 cache metro   # 수원 4구·분당·동안·동탄구 → sl_YYYYMMm.json.gz (약 840회 호출, 3분)
    python3 tools/extract_trades.py                # cache → data/complex_trades.json.gz (단지 6,154개)
    python3 build_data.py [YYYY-MM-DD]             # → site/data/ (기본 기준일 = 두 달 전 월말)
    python3 history.py                             # → site/data/hist.json (10년 분기 지수·하락기 방어력)
    python3 -m http.server 8002 --bind 127.0.0.1 -d site   # http://127.0.0.1:8002/
    python3 -m pytest -q                           # 데이터 8 + 화면 55 + 독립 검증 verify/ 7 (헤드리스 Chrome 필요)
    python3 tools/validate_downturn.py             # 과거 16개 시점 엔진 검증(독립 지수·단순 기준 대비)
    python3 tools/report_history.py                # 구별 방어력·선후행·월별 건수 리포트

URL 오버라이드(테스트용): `#/plan?b=<id>&sale=&buy=&aloan=&bloan=&cash=&move=&tax=` (만원), `?theme=dark&nosplash&nomotion`. `income`·`debt`도 `#/find`·`#/plan` 주소로 넣을 수 있지만 테스트용입니다. 앱이 소득을 주소에 쓰지는 않으나, 이렇게 연 주소는 주소창에 소득이 남으니 공유하지 마세요.

## 엔진 (build_data.py)

단지별 ln(㎡당가) ~ 시간 + 층대 + 평형 최소제곱, 표준오차 ×1.2로 90% 범위, ±3% 임계로 상승/주춤/하락, 범위가 임계를 넘으면 "확실".

- **6개월 추세(현행)** = (24개월 창 '최근 6개월 속도' 모델 + 12개월 선형)의 평균. 범위는 두 모델 중 넓은 쪽.
  - 이전의 24개월 단순 직선은 방향 전환을 늦게 잡았습니다(2022-06 하락 단지 72개 중 0개 재현, 독립 지수 대비 평균 오차 -13%~+17%). 결합안(운영 기준)은 2022-06~2023-03 하락 단지 재현 75~92%(2023-03은 92%), 독립 지수 대비 평균 오차 -4.5%~+2%입니다. 완만한 구간(2024~2026)의 하락 재현은 20~38%로 낮습니다(독립 지수 자체도 잡음).
- 최근 12개월 거래가 12건 미만이거나, 최근 3개월 거래가 2건 미만(꺾임 모델이 마지막 거래 이후를 외삽해 극단값을 내므로)이거나, 꺾임 모델을 못 맞추면 24개월(없으면 36개월) 평균만 계산해 **"참고용"**으로 표시합니다(상승/주춤/하락 라벨·주변 비교 없음, 항상 추정).
- 그래도 부족하면 "표본 부족"(최근 12개월 중위값만).

## 10년 분석 (history.py)

분기 지수(백피팅: 분기+평형+층대 효과)로 단지별 10년 흐름을 만들고, 2020Q4~2022Q4 고점 → 2024Q2까지 저점의 낙폭과 회복 분기를 계산합니다. 분기 거래 3건 미만은 비웁니다. 지수가 만들어지는 단지는 3,630개, 하락기 방어력은 분기 거래가 충분한 1,201개에만 있습니다.

## 한계 (화면에도 표시)

- **수록 범위**: 위 지역의 10년 합계 거래 12건 이상 단지 6,154개. 나머지 수도권은 없습니다(화성은 2026-07 코드 개편 후 동탄구 41597만 수집). 상승/주춤/하락 라벨은 최근 거래가 충분한 2,093개에만 붙습니다.
- **원본 데이터**: 취소 표시는 2020-02부터, 거래유형(직거래)은 2021-11부터 있어 그 이전 구간은 취소·직거래를 제외하지 못합니다(초기 ㎡당가가 낮게 치우칠 수 있고 10년 지수·방어력에 영향). 신고 지연으로 최근 1~2개월 건수는 적습니다.
- **검증의 한계**: '독립 분기 지수'(같은 원천 데이터, 다른 방법)와의 비교이며 정답 라벨이 없습니다. 결합안은 같은 기간 데이터로 고른 방식이라 낙관적일 수 있습니다(선택에 쓰지 않은 4개 시점도 상관 0.51~0.93). 거래 수 가드로도 막지 못하는 과장 사례가 남아 있습니다(최근 3개월에 다른 평형 거래만 있는 단지).
- **방어력**: 분기별 거래가 적으면 고점·저점이 잡음에 끌리고, 거래가 활발한 단지에 치우칩니다.
- **자금 계획**: 취득세(1주택·일시적 2주택 가정), 중개보수(서울시·경기도 조례 요율표+한도액), 법무·등기 0.3%는 추정/확인 필요. 양도세는 입력값(12억 기준 안내만), 대출은 연소득을 입력하면 LTV·상한·DSR(스트레스 금리 가산)로 계산하고 금리·만기는 가정값입니다. 일시적 2주택 처분기한 등은 안내만 합니다.
- **규정 값**: `site/data/rules.json`(기준일·출처·확인 상태, 90일 초과 시 경고)에 분리했습니다. 금리 4.0%·만기 30년·전세가율 60%는 가정값입니다. 남양주 다산동·수원 권선구는 규제·토허제 지정 목록에 없어 비규제로 가정했고, 동탄구의 지정 경계는 공식 고시와 대조하지 못했습니다.
- **예시와 편집**: 첫 실행 예시 후보는 관악구 벽산블루밍·노원구 한진한화그랑빌(85㎡)로 고정(`app.js EXAMPLES`). 각 카드의 ⋮ 메뉴에서 평형·층(대) 변경, A는 다른 단지로 변경·취득 정보 수정, B는 삭제할 수 있고, 단지 상세에서 평형 칩을 고른 뒤 "이 평형으로 저장"/"후보에 추가"도 가능합니다.
