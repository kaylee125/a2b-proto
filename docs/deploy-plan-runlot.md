# runlot으로 "갈아탈까" 배포하기 — 이해와 계획

작성일 2026-10-14. runlot 내용은 **공식 문서(docs.runlot.io)를 읽은 결과**이고, 직접 CLI를 실행해 확인한 것은 아니다. 문서에 없는 항목은 "미확인"으로 표시했고, 미리보기 배포에서 실측하는 단계를 계획에 넣었다.

---

## 1. runlot이 무엇인가 (쉬운 설명)

**한 줄**: 서버를 직접 만들지 않고, 명령 한 줄(`runlot deploy`)로 웹사이트나 작은 API를 인터넷에 올려주는 호스팅 서비스다. 이름처럼 서버(DB, 로그인, 파일 저장소, 이메일, AI)까지 한 프로젝트에 묶어 제공한다.

**비유**: 가게를 열 때 건물을 짓는 대신 "빈 점포를 빌려 간판만 거는" 방식이다. 우리는 점포(호스팅)와 주소(`이름.조직.runlot.app`)를 빌리고 물건(`site/` 폴더)만 올린다.

**`github.com/runlot`의 정체**: 배포 도구가 아니라 runlot의 **회사 소개 페이지**다(저장소 3개: Helm 차트, DB 엔진 colibri, 프로필). 우리가 쓰는 것은 npm으로 설치하는 **CLI**와 **runlot.io 계정**이다. GitHub 저장소를 연결해서 배포하는 방식이 아니라, **내 컴퓨터에서 `runlot deploy`를 실행**해 올리는 방식이 기본이다.

| runlot이 주는 것 | 우리가 쓰나? |
|---|---|
| 정적 파일 호스팅(HTML·JS·CSS·JSON) | **쓴다** (`site/` 폴더 전체) |
| 기본 주소 `이름.조직.runlot.app` + 자동 HTTPS | **쓴다** |
| 커스텀 도메인(CNAME+TXT), 인증서 자동 | 나중에 선택 |
| 접근 제어(public / org / password) | 쓴다(베타 때 비밀번호) |
| 미리보기 배포, 버전 롤백, 로그, 사용량 | 쓴다 |
| PostgreSQL, 로그인, 파일 저장소, 이메일, AI | **안 쓴다** (서버에 저장하는 정보 없음) |

## 2. 우리 서비스와 얼마나 잘 맞나

우리 서비스는 **서버가 필요 없는 정적 사이트**다. 입력값은 브라우저(`localStorage`)에만 저장하고, 계산도 브라우저에서 하며, 데이터는 미리 만들어 둔 JSON 파일이다. 그래서 runlot의 "정적 파일만 배포" 방식이 그대로 맞는다.

**실측한 `site/` 폴더 vs runlot 제한**

| 항목 | 우리 | runlot 제한 | 판정 |
|---|---|---|---|
| 파일 수 | 6,259개 | 20,000개 | 통과 (31%) |
| 압축 업로드 크기 | 4.4 MB | 64 MiB | 통과 |
| 압축 해제 후 크기 | 약 29 MB | 512 MiB | 통과 |
| 가장 큰 파일 | 1.59 MB(`index.json`) | 64 MiB | 통과 |
| 숨김 파일·심볼릭 링크 | 없음 | 심볼릭 링크 거부 | 통과 |
| 라우팅 | 주소의 `#/…`(해시) | 서버 라우팅 불필요 | 통과 |

**방문 한 번의 요청 수**(추정): 화면 파일 3개 + 데이터 4~5개 + 단지 상세 JSON 몇 개 = 10~15건. 무료 한도(하루 100,000건)면 **하루 약 7천~1만 방문**까지 감당한다(추정). 한도를 넘으면 그날은 `429`로 응답이 멈추고 다음 날 UTC 00:00에 풀린다(요금은 청구되지 않음).

**개인정보 관점**: 소득·현금 같은 입력은 서버로 가지 않는다. 주소의 `#` 뒤(`#/find?income=…`)는 브라우저가 서버로 보내지 않아 runlot 로그에도 남지 않는다.

## 3. 배포 구조

```
a2b-proto/
  runlot.json        ← 새로 추가 (설정 3줄)
  site/              ← 이 폴더 전체가 배포됨 (index.html, app.js, style.css, data/)
  (그 밖의 build_data.py, tests, cache/ 등은 배포되지 않음)
```

`runlot.json` (문서의 정적 사이트 방식: `main` 없이 `assets`만):

```json
{ "name": "galatalkka", "assets": "site" }
```

- `name`은 주소의 첫 칸이 된다. 규칙: **소문자·숫자·하이픈만, 최대 30자, 하이픈 두 개(`--`) 금지**(한글 불가). 예: `galatalkka`(10자) → `galatalkka.<조직>.runlot.app`
- **조직 슬러그는 한 번 정하면 바꿀 수 없다**(같은 이름 규칙). 주소에 그대로 들어가므로 신중히 정한다.
- `main`을 빼면 "모든 요청을 정적 파일로 보내는 진입점"이 자동 생성된다.
- 헤더·캐시·리다이렉트를 설정하는 항목은 **문서에 없다**(→ 리스크 2).

## 4. 작업 계획

**역할**: 🅰 = 제가 하는 로컬 작업(코드·테스트·점검), 🅱 = 직접 해 주셔야 하는 작업(계정·로그인·공개 결정). 배포는 외부에 공개되는 일이라 🅱가 확인한 뒤에만 진행한다.

### 작업 목록

| # | 작업 | 역할 | 방법 / 명령 | 완료 기준 | 시간 |
|---|---|---|---|---|---|
| T1 ✅ | 배포 설정 파일 | 🅰 | `a2b-proto/runlot.json` = `{ "name": "galatalkka", "assets": "site" }` (org는 로그인 후 `--org` 또는 파일에 추가) | 파일 생성, `site/`가 assets로 지정됨 | 5분 |
| T2 ✅ | 데이터 캐시 안전장치 | 🅰 | `app.js`가 JSON을 읽을 때 `index.html`의 `?v=` 값을 붙임(`data/index.json?v=27`). 월간 갱신 때 `?v=` 한 곳만 올리면 코드·데이터 캐시가 함께 갱신됨. 헤더를 설정할 수 없어 필요 | 화면 테스트 통과, 데이터 요청에 `?v=`가 붙음 | 20분 |
| T3 ✅ | 베타 검색 노출 방지 | 🅰 | `index.html`에 `<meta name="robots" content="noindex">` (일반 공개 때 제거) | 메타 태그 존재 | 5분 |
| T4 ✅ | 배포 전 점검 | 🅰 | `pytest` 전체, `site/`에 비밀 값·불필요 파일 없는지 `grep`/`find`, 파일 수·압축 크기 재측정(6,259개·4.4MB) | 통과, `site/`에 임시 파일 없음 | 15분 |
| T5 | runlot 가입·로그인 | 🅱 | `dash.runlot.io`에서 계정 생성(카드 요구 여부는 문서에 없음, 가입 중 확인) → 터미널에서 `! npm i -g runlot` → `! runlot login`(브라우저 로그인) → `! runlot whoami`. **조직 슬러그를 정한다(변경 불가)** | `whoami`에 계정·조직이 보임 | 15분 |
| T6 | **미리보기 배포** | 🅱 확인 후 🅰 실행 | `cd a2b-proto && runlot deploy --preview beta` (운영과 분리된 별도 주소). 출력 예: `Bundling… Uploading… Deploying… v1 <주소>` | 주소가 출력되고 열림, `bundle_too_large`·`not_a_member` 오류 없음 | 15분 |
| T7 | **미리보기 실측** | 🅰 | 헤드리스 Chrome·`curl`로 점검: ①6개 화면+온보딩 열림 ②응답 헤더(`Content-Type`, `Cache-Control`, 압축) ③없는 경로의 응답 ④`#/c/<id>` 새로고침 ⑤첫 로드 시간·요청 수 ⑥기본 접근 모드(`runlot access`) | 점검표 전부 기록, 문제 있으면 원인과 대응 | 30분 |
| T8 | 접근 모드 설정 | 🅱 | `runlot access set password`(지인 공개) — 비밀번호를 걸어도 우리 앱의 데이터 요청이 되는지 T7에서 같이 확인 | 비밀번호 없이는 열리지 않고, 입력하면 정상 동작 | 10분 |
| T9 | **운영 배포** | 🅱 확인 후 🅰 실행 | `runlot deploy` → `runlot versions`로 현재 버전 확인 | 운영 주소에서 T7 점검표 재통과 | 10분 |
| T10 | 팀 공유 | 🅱 | 주소+비밀번호 전달, 첫 화면 안내(가이드가 자동으로 한 번 뜸) | 동료가 접속해 시나리오 수행 | — |
| T11 ✅ | 운영 문서 | 🅰 | `docs/deploy-runbook.md` (배포·롤백·점검표·월간 갱신) | 문서 생성 | 20분 |
| T12 | 이후(선택) | 🅱🅰 | GitHub 저장소(`kaylee125/a2b-proto`)에서 자동 배포(`runlot token create ci --scope deploy` → `RUNLOT_TOKEN` 시크릿), 커스텀 도메인(`runlot domain add/verify`, CNAME+TXT), 일반 공개(`access set public`, noindex 제거) | 각각 별도 승인 | — |

### 일정 (내일 팀 공유 기준)
- **오늘**: T1~T4(🅰, 약 45분) → T5(🅱, 15분) → T6~T7(미리보기 배포·실측, 약 1시간). 이 시점에 문제가 있으면 내일 아침 전에 해결한다.
- **내일 오전(공유 전 30분)**: T8~T9(접근 모드·운영 배포) → T10(공유).
- **막히면 대안**: 가입·로그인·배포가 안 되면 같은 사무실 네트워크 공유(내 컴퓨터에서 서버를 `0.0.0.0`으로 띄우는 방법)로 먼저 공유하고 runlot은 이후 진행한다.

### 중단·롤백 기준
- 미리보기에서 핵심 화면이 안 열리거나, 데이터 요청이 실패하면(404/403) 운영 배포를 하지 않는다.
- 운영 배포 후 문제가 보이면 `runlot versions` → `runlot rollback <이전 버전>`(확인 요청이 뜨고, 이전 버전을 다시 켜는 방식이라 빠르다. 버전은 삭제되지 않고 개수 제한이 없다).
- 한도 초과로 그날 서비스가 멈추면 다음 날 UTC 00:00(한국 시간 09:00)에 풀린다.

### 진행 상황 (2026-10-14)
- **T1~T4, T11 완료.** `runlot.json` 추가, 데이터 요청에 `?v=` 부착(8개 요청 모두 확인), `noindex` 추가, `pytest` 103개 통과, `site/`에 비밀 값·숨김 파일·심볼릭 링크 없음(6,259개 파일, 압축 4.4MB). 배포 제한을 자동으로 지키는 테스트도 추가했다.
- **다음은 🅱 T5**(가입·CLI 설치·로그인). 이후 T6~T7은 제가 이어서 한다.

### CLI에 대한 추가 확인 (npm 레지스트리 조회, 설치 전)
- 패키지 `runlot` 최신 버전이 **`0.1.0-rc.145`**(정식 1.0 전 릴리스 후보), 생성 2026-09-08(약 5주 전), 마지막 수정 2026-10-13, **게시자는 개인 1명**이다. 저장소 주소는 `github.com/runlot/runlot`이나 조직 페이지에는 공개 저장소로 보이지 않는다(제품 코드는 비공개라고 명시).
- 좋은 점: 설치 스크립트(`preinstall`/`postinstall`)가 **없고**, 의존성은 `esbuild`와 `@electric-sql/pglite` 둘뿐이다.
- 주의: 13.6MB짜리 번들 파일 하나라 내용을 직접 검토하기 어렵고, 이 도구는 로그인 토큰을 저장(`~/.runlot/credentials.json`)하고 우리 폴더를 업로드한다. 올리는 것은 공공 실거래 가공 데이터뿐이라 영향은 작지만, **설치 여부는 직접 판단**해야 한다.
- 이 환경은 npm 보안 검사(SCFW)가 켜져 있어, 비대화형 설치는 경고 시 차단될 수 있다. 터미널에서 직접(`! npm i -g runlot`) 실행하는 것이 맞다.

### 새로 확인된 사실 (이번 조사)
- `runlot deploy [디렉터리]`는 **빌드를 로컬에서** 한다(원격 빌드 없음). 옵션은 `--org`, `--project`와 미리보기용 `--preview <이름>`.
- 롤백은 `runlot rollback <버전>`, 새 빌드 없이 기존 결과를 다시 켠다. 데이터베이스는 롤백되지 않는데 우리는 DB를 쓰지 않아 영향이 없다.
- 요청이 5분 없으면 자동 중지되고, 다음 요청에 깨어난다(전형적 첫 요청 지연 약 0.36초, 보장값 아님). 정적 사이트에도 같은 방식이 적용되는지는 문서에 없다.
- 요금제는 Free($0)와 Pro($20/월)이고, 문서에 "현재 셀프 서비스 업그레이드는 열려 있지 않으며 모든 조직이 Free"라고 되어 있다. 하루 10만 요청을 넘으면 늘릴 방법이 당장은 없을 수 있다.
- 새 프로젝트의 기본 접근 모드, 번들 규칙(Bundle rules), 개인 액세스 토큰 문서는 확인하지 못했다. T7에서 실측하고 T12 전에 다시 읽는다.
